# Volanchiki — новостные инсайты для руководителей крупного бизнеса

Хакатон «Альфа-Будущее»: *Новостная аналитика для принятия бизнес-решений*.

Сервис берёт **клиента** (юрлицо из обезличенной выборки) и **событие** (новость или тема), а возвращает не пересказ, а **персональный инсайт**: что произошло, почему это важно именно этой компании, как событие оценивает Альфа-Банк, какие риски и возможности, что делать дальше. Каждый вывод помечен происхождением и привязан к источникам.

> **Демо:** `https://ВАШ-ДОМЕН` (впишите после деплоя) · **Версия для проверки:** commit `ВПИШИТЕ_HASH`

## Что видит пользователь

1. **Главный экран** макета Альфа-Бизнеса с заметным виджетом «Новостные инсайты» и боковой кнопкой — постоянная точка входа.
2. **Выбор клиента** из демо-списка или поиск; справа профиль: вид деятельности, выручка, регион, группа, продукты банка.
3. **Выбор события**: готовые темы из аналитики банка или своя новость (любой текст).
4. **Инсайт** по шести вопросам кейса, с бейджами происхождения:
   - 🟦 **Факт из источника** (синяя рамка) — что произошло;
   - 🟥 **Позиция Альфа-Банка** (красная рамка) — только из аналитических материалов банка;
   - 🟪 **Вывод AI** (фиолетовая рамка) — гипотеза модели по данным о компании.
5. **«Как мы это посчитали»** — трассировка шагов агента; **«На чём основан вывод»** — источники и цитаты.

## Как это работает

```
Браузер (React + TS)  ──/api──►  ASP.NET Core 8 API
                                   │
                    ┌──────────────┼──────────────────┐
                    ▼              ▼                  ▼
              CompanyStore   AlfaAnalyticsStore    LlmClient
              (3 CSV: компании,  (txt-аналитика    (шлюз организаторов,
               физлица, платежи) банка, поиск)      разрешённые модели)
                    └──────────────┬──────────────────┘
                                   ▼
                          AgentOrchestrator
        get_company_profile → search_alfa_analytics → draft_insight → самопроверка → (доработка)
```

**Агент** (`src/Volanchiki.Api/Agent`) выполняет многошаговый процесс с общим контекстом (`AgentSession.Scratch`):

| Шаг | Инструмент | Что делает |
|---|---|---|
| 1 | `get_company_profile` | профиль, продукты, группа компаний, крупнейшие платёжные связи |
| 2 | `search_alfa_analytics` | ищет релевантные фрагменты в материалах банка |
| 3 | `draft_insight` | собирает JSON-инсайт; позиция банка берётся только из найденной аналитики |
| 4 | самопроверка | лёгкая модель проверяет связь с компанией и обоснованность; при замечаниях — повторный черновик |

Каждый шаг пишется в трассировку (`AgentTraceStep`), она возвращается вместе с инсайтом.

## Запуск

Нужно: **.NET SDK 8** (в `global.json` указан 9.0.201 с `rollForward` — подойдёт любой SDK ≥ 8; если ругается, поправьте `global.json`) и **Node.js 20+**.

```bash
cp .env.example .env        # впишите LLM_API_KEY
```

**Бэкенд** (порт 5080):
```bash
dotnet run --project src/Volanchiki.Api --launch-profile http
```

**Фронтенд** (порт 5173, `/api` проксируется на бэкенд):
```bash
cd frontend
npm install
npm run dev
```
Откройте http://localhost:5173.

**Только интерфейс без бэкенда и ключа** (заглушки):
```bash
cd frontend && npm install && npm run dev:mock
```

**Одной командой через Docker:**
```bash
docker compose up --build   # http://localhost:8080
```

Деплой на сервер без Docker: [docs/DEPLOY.md](docs/DEPLOY.md).

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_API_KEY` | ключ шлюза (общий, лимит 500 ₽/день) | — |
| `LLM_BASE_URL` | адрес шлюза | см. `.env.example` |
| `LLM_USE_SYSTEM_PROXY` | использовать системный прокси | `false` |
| `API_PORT` | порт API | `5080` |
| `DATA_COMPANY_DIR`, `DATA_ALFA_DIR` | папки с данными | `read_only/...` |
| `VITE_API_BASE` (фронт) | адрес API, если не тот же домен | пусто |
| `VITE_USE_MOCK` (фронт) | включить заглушки | `false` |

## Сценарий проверки (3 минуты)

1. Откройте демо. На главной нажмите **«Открыть»** в красном виджете.
2. Выберите первую компанию; проверьте профиль справа.
3. Оставьте событие «ЦБ сохранил ключевую ставку 14%» → **«Получить инсайт»** (20–90 сек).
4. Сверьте бейджи: факт / позиция банка / вывод AI. Раскройте **«Как мы это посчитали»**.
5. Выберите **другую компанию** и повторите — акценты и риски должны отличаться.
6. Вставьте **собственную новость**, которой нет в списке, и запустите заново.

## Безопасность и ограничения

- Ключ LLM хранится только в `.env` на сервере, в браузер не попадает; `.env` в `.gitignore`.
- Данные клиентов обезличены; в LLM уходит профиль без реальных реквизитов.
- Все обращения к инструментам агента пишутся в трассировку.
- Только разрешённые кейсом модели; суточный лимит токенов общий на команду.

**Что пока не сделано** (честный список): сбор новостей из внешних источников (сейчас событие задаёт пользователь); уточняющие вопросы к инсайту; ранжированная лента событий; сохранение обратной связи на сервере (кнопки 👍/👎 пока локальные); защита от prompt injection в тексте новости; метрики качества.

## Масштабирование и поддержка

Новые отрасли и клиенты — это новые строки в CSV; новые источники аналитики — новые txt/PDF в `read_only/from_alfa` (хранилище читает каталог целиком); новые инструменты агента — класс, реализующий `IAgentTool`, и одна строка регистрации в `Program.cs`.
