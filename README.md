# Volanchiki — новостные инсайты для руководителей крупного бизнеса

Хакатон «Альфа-Будущее»: Новостная аналитика для принятия бизнес-решений.

> **Демо:** https://alfa.dev.news.myrelo.ru
> **Версия для проверки:** commit `5656f7d`

## Назначение

Сервис берёт **клиента** (юридическое лицо из обезличенной выборки) и **событие** (новость из открытых RSS, тема из аналитики банка или свой текст) и возвращает **персональный инсайт**:

1. что произошло;
2. почему это важно именно для этой компании;
3. какие последствия, риски и возможности возможны;
4. какие действия могут быть релевантны;
5. как событие оценивает Альфа-Банк;
6. на чём основан вывод (источники).

## Что видит пользователь (сквозной сценарий)

1. **Главный экран** макета интернет-банка «Альфа-Бизнес» с заметным виджетом «Новостные инсайты» и постоянным пунктом в верхнем меню — точка входа в сервис.
2. **Выбор клиента**: демо-список или поиск; справа профиль компании (вид деятельности, выручка, регион, группа, продукты банка).
3. **Выбор события**: лента из открытых RSS (ТАСС, РИА Экономика, Lenta, Интерфакс), быстрые темы из аналитики банка или произвольный текст.
4. **Инсайт** с тремя цветными рамками, чтобы было видно происхождение каждого вывода:
   - **Факт из источника** (синяя рамка) — что произошло, по новости;
   - **Позиция Альфа-Банка** (красная рамка) — только из аналитических материалов банка;
   - **Вывод AI** (фиолетовая рамка) — гипотеза модели по данным о компании, не позиция банка.
5. **«Как мы это посчитали»** — трассировка шагов агента; **«На чём основан вывод»** — источники со ссылками и цитатами.
6. Рисков, возможностей и следующих действий — отдельные блоки; внизу кнопка «Связаться с менеджером» и дисклеймер.

## Пошаговая проверка для эксперта

Вариант A — открыть демо (ничего устанавливать не нужно):

1. Откройте https://alfa.dev.news.myrelo.ru. На главном экране найдите виджет «Новостные инсайты» и пункт «Новостные инсайты» в верхнем меню.
2. Нажмите «Новостные инсайты». Выберите клиента из демо-списка (или найдите по идентификатору, виду деятельности, городу или группе).
3. Проверьте профиль справа: отрасль, выручка, регион, группа компаний, продукты банка.
4. Выберите событие: нажмите на новость из живой ленты, на быструю тему или впишите собственный текст. Смените клиента и убедитесь, что лента новостей и ранжирование меняются под клиента.
5. Нажмите «Получить инсайт». Расчёт занимает от нескольких секунд до полутора минут. Во время расчёта показывается ход выполнения.
6. Проверьте результат: три рамки (факт / позиция банка / вывод AI), риски, возможности, действия, источники.
7. Откройте «Как мы это посчитали» и убедитесь, что видны вызовы инструментов: профиль компании, поиск новостей, поиск по аналитике банка, сборка инсайта, самопроверка.
8. Повторите шаги 2–7 для другого клиента и другого события — результат должен отличаться.

Вариант Б — запуск у себя: см. раздел «Запуск». Без ключа LLM интерфейс и данные работают, но вместо инсайта выдаётся шаблонный «Черновик (без LLM)», а доклассификация новостей моделью отключена.

## Агентная логика

AI-компонент не ограничивается одной генерацией: оркестратор (`Agent/AgentOrchestrator.cs`) последовательно вызывает инструменты, хранит результаты шагов в общем контексте прогона и проверяет итог.

| Инструмент | Что делает | Откуда берёт данные |
|---|---|---|
| `get_company_profile` | профиль клиента: ОКВЭД, регион, группа, продукты, платежи | CSV из `read_only/company` |
| `search_news` | поиск и ранжирование новостей под клиента и событие | RSS-лента в памяти (`NewsStore`) |
| `search_alfa_analytics` | поиск фрагментов аналитики Альфа-Банка | txt из `read_only/from_alfa` |
| `draft_insight` | сборка структурированного JSON-инсайта | LLM (роль Reasoning) по результатам трёх предыдущих шагов |

- **План.** Порядок шагов задан кодом (профиль → новости → аналитика банка → черновик): он детерминирован, потому что модель в роли планировщика зацикливалась. Результаты каждого шага попадают в общий контекст (`AgentSession.Scratch`) и используются следующими шагами.
- **Самопроверка.** После сборки лёгкая модель проверяет карточку (`SelfCheckAsync`); при отрицательном вердикте черновик пересобирается один раз. Если черновик не удалось разобрать, показывается шаблон с явной пометкой.
- **Формат обмена.** Инсайт — JSON с отдельными полями `what_happened`, `why_matters_for_company`, `bank_view`, `model_view`, `risks`, `opportunities`, `suggested_actions`, `relevance`, `sources`. Поле `bank_view` отделено от `model_view`, на этом основано разделение «позиция банка» / «вывод AI» в интерфейсе.
- **Трассировка.** Каждое действие агента пишется в `trace` ответа (какой инструмент, результат шага в сокращённом виде) и показывается в интерфейсе.

### REST API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние сервиса, загружены ли данные |
| GET | `/api/companies/demo?take=` | демо-клиенты |
| GET | `/api/companies?q=&take=` | поиск клиентов |
| GET | `/api/companies/{id}` | профиль клиента, группа, платежи |
| GET | `/api/news?q=&companyId=&take=` | лента; при `companyId` ранжируется под клиента |
| POST | `/api/insights/run` | тело `{ "companyId": "...", "newsHint": "..." }` → `{ runId, status }` |
| GET | `/api/insights/runs/{runId}` | статус прогона и результат (инсайт + трассировка) |

Коллекция запросов: `postman/volanchiki.postman_collection.json`.

### Новости

Фоновый сервис раз в ~3 минуты читает публичные RSS, убирает дубли и кладёт новости в память. **Рубрики** (Ставка, Инфляция, Макро, Валюта, Нефть, Металлы, Финансы, Санкции, Бизнес, Торговля, Регион, Прочее): однозначные назначаются правилами, спорные и неопознанные уточняет лёгкая LLM (`News:LlmClassifyPerPoll`, по умолчанию 15 за опрос). Модель отвечает только допустимыми рубриками: ответ с неизвестной рубрикой отбрасывается, новость возвращается в очередь. Если RSS недоступны, используются синтетические демо-новости (помечены как `isSeed`).


## Требования к окружению

| Вариант | Что нужно |
|---|---|
| Docker | Docker и Docker Compose |
| Локально | **.NET SDK 8** и **Node.js 20+** (проверено на Node 22) |

Версии зафиксированы: `global.json` (SDK), `frontend/package-lock.json` (npm), версии пакетов в `*.csproj`, базовые образы в `Dockerfile` (`node:22-alpine`, `dotnet/sdk:8.0`, `dotnet/aspnet:8.0`).

## Запуск

Скопируйте шаблон настроек и впишите ключ шлюза LLM:

```bash
cp .env.example .env        # впишите LLM_API_KEY
```

**Одной командой через Docker** (фронтенд и бэкенд в одном контейнере):

```bash
docker compose up --build   # http://localhost:8080
```

**Локально.** Бэкенд (порт 5080):

```bash
dotnet run --project src/Volanchiki.Api --launch-profile http
```

Фронтенд (порт 5173, `/api` проксируется на бэкенд):

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173.

**Только интерфейс без бэкенда и ключа** (данные-заглушки):

```bash
cd frontend && npm ci && npm run dev:mock
```

**Свой сервер без Docker** (nginx + systemd): см. [docs/DEPLOY.md](docs/DEPLOY.md).

## Конфигурация и переменные окружения

Переменные читаются из окружения или из файла `.env` в корне репозитория.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_API_KEY` | — | ключ доступа к шлюзу LLM (**обязателен** для инсайтов и доклассификации новостей) |
| `LLM_BASE_URL` | `https://changellenge.up.railway.app/v1` | адрес OpenAI-совместимого шлюза |
| `LLM_MODEL_LIGHT` | `google/gemma-4-26b-a4b-it` | лёгкие задачи: классификация новостей, самопроверка |
| `LLM_MODEL_REASONING` | `z-ai/glm-5.3-flash` | сборка инсайта |
| `LLM_MODEL_DEFAULT` | `qwen/qwen3.6-35b-a3b` | универсальная роль |
| `LLM_MODEL_RESEARCH` | `deepseek/deepseek-v4.1-flash` | исследовательская роль |
| `LLM_USE_SYSTEM_PROXY` | `false` | ходить к шлюзу через системный прокси |
| `DATA_COMPANY_DIR` | `read_only/company` | каталог CSV клиентов |
| `DATA_ALFA_DIR` | `read_only/from_alfa` | каталог txt аналитики банка |
| `NEWS_POLL_SECONDS` | `180` | период опроса RSS |
| `ASPNETCORE_ENVIRONMENT` | `Development` | режим ASP.NET |

Список RSS-лент и `LlmClassifyPerPoll` задаются в `src/Volanchiki.Api/appsettings.json` (`News:Feeds`, `News:LlmClassifyPerPoll`).

## Данные

- `read_only/company/*.csv` — обезличенные данные клиентов, связанных лиц и платежей (выданы организаторами). Идентификаторы используются только для анализа связей внутри выборки.
- `read_only/from_alfa/*.txt` — аналитические материалы Центра макроэкономических исследований Альфа-Банка (выданы организаторами).
- Внешние новости — публичные RSS. Заголовки и аннотации хранятся только в памяти на время работы сервиса.
- Синтетические темы для офлайн-демо — `frontend/src/events.ts` и seed-новости бэкенда.

Данные кейса и новости синтетические или публичные; для сквозной проверки отдельные тестовые учётные записи не требуются: вход в интернет-банк в прототипе смоделирован макетом.
