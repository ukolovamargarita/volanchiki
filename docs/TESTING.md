# Тесты

В проекте два набора тестов. Они **не ходят в сеть и не тратят токены LLM**: проверяют логику, которую можно проверить честно.

| Набор | Где лежит | Чем запускается | Что проверяет |
|---|---|---|---|
| Бэкенд (xUnit) | `tests/Volanchiki.Tests/` | `dotnet test tests/Volanchiki.Tests` | классификатор новостей, RSS/Atom-парсер, хранилище и поиск новостей, поиск по аналитике банка, загрузка txt, хранилище компаний |
| Фронтенд (Vitest) | `frontend/src/**/*.test.ts(x)` | `cd frontend && npm test` | форматтеры, API-слой, разметка «факт / банк / AI», выбор события, сценарий выбора компании и запуска инсайта |

## Запуск

```powershell
# бэкенд (из корня репозитория)
dotnet test tests/Volanchiki.Tests

# фронтенд
cd frontend
npm install
npm test
```

Команду нужно давать именно с путём `tests/Volanchiki.Tests`: в корне лежат и `volanchiki.sln`, и `Volanchiki.slnx`, поэтому просто `dotnet test` ответит «найдено несколько решений».

Тест `Real_bank_analytics_load_and_rate_query_finds_policy_rate_report` читает настоящие файлы из `read_only/from_alfa`, поэтому запускать бэкенд-тесты нужно из клона репозитория с этой папкой.

## Что специально НЕ покрыто (и почему)

- **Вызовы LLM и итоговый текст инсайта.** Ответ модели недетерминирован и тратит лимит 500 ₽. Тест «модель написала хорошо» был бы выдуман. Качество текста проверяется на золотом наборе вручную или LLM-судьёй (критерий 08 кейса).
- **Загрузка CSV (`CsvCompanyLoader`) и HTTP-контроллеры.** Это нужно проверять интеграционно (`WebApplicationFactory`), для этого нужен пакет `Microsoft.AspNetCore.Mvc.Testing`. Тесты ниже написаны только на то, что реально запускалось.
- **Оркестратор агента (`AgentOrchestrator`).** Его логика приватная; чтобы тестировать её, нужен `InternalsVisibleTo` либо выделение чистых функций.
- **RSS из интернета.** Парсер проверяется на встроенных примерах XML, не на живых лентах.

## Известная проблема, зафиксированная тестом

Тест `Does_not_match_keyword_inside_unrelated_word` помечен `Skip`. Он описывает правильное поведение и сейчас падает: классификатор ищет слова по подстроке, поэтому «Реакция зрителей…» попадает в «Финансы» (внутри «реакция» есть «акци»). Когда исправите классификатор (например, сравнением по границам слов), уберите `Skip` — тест станет проверкой исправления.

## Как добавлять свои тесты

- Бэкенд: новый файл `tests/Volanchiki.Tests/ИмяТests.cs`, класс с методами `[Fact]` (один сценарий) или `[Theory]` + `[InlineData(...)]` (таблица примеров). Готовые фабрики данных: `TestData.News(...)`, `TestData.Co(...)`.
- Фронтенд: файл `имя.test.ts(x)` рядом с проверяемым файлом. Сеть подменяется через `vi.mock("../api")`, тестовые данные лежат в `src/test/fixtures.ts`.
- Правило честных тестов: сначала запишите, что **должно** происходить, потом запускайте. Если тест падает, это либо ошибка в коде, либо в вашем ожидании, и нужно выяснить, что именно. Подгонять ожидание под текущий результат нельзя.

## Известная проблема, зафиксированная тестом

Тест `NewsClassifierTests.Keyword_inside_an_unrelated_word_does_not_give_a_confident_category` помечен `Skip`: ключ «акци» (4 символа) ищется как подстрока, поэтому «Реакция зрителей на премьеру…» получает рубрику «Финансы» без проверки моделью. Когда правило поправят, уберите `Skip` — тест должен стать зелёным.
